## The commands

```sh
# 1. A worktree at the head of the PR. The directory is named after the repo on
#    purpose: meta.repo is basename(--repo), so a worktree called anything else
#    writes that name into the map.
git -C ~/Projects/checkride/code/checkride worktree add /tmp/atis-spike/checkride ae5078c --detach

# 2. Its own pinned toolchain, and the .check/ that atis reads for evidence.
#    The run exits 1: the security slot is red (see "What the category means" below).
cd /tmp/atis-spike/checkride
pnpm install
pnpm check --all --skip mutation

# 3. The map. --repo takes the resolved path, not the /tmp symlink: on macOS
#    /tmp is /private/tmp, and istanbul's absolute coverage keys will not
#    relativise against the unresolved one, which silently empties
#    weather.evidence.patch_coverage.
cd ~/Projects/atis/code/atis
node apps/atis/dist/cli.js \
  --repo "$(cd /tmp/atis-spike/checkride && pwd -P)" \
  --base fee5ed6 \
  --out fixtures/checkride-pr4/map.json

# 4. The worktree is not kept.
git -C ~/Projects/checkride/code/checkride worktree remove --force /tmp/atis-spike/checkride
rm -rf /tmp/atis-spike
```

### What the category means

The `security` slot is red, which is what makes the map IFR. `pnpm audit` runs against
today's advisory database rather than the one that existed when PR 4 merged, so the 15
advisories it reports are a property of the lockfile's age and not of the change. The map
is honest about it — the notice reads *the `security` check is red for the whole
repository*, scoped `global` — but a reader judging this PR should know the category is
carrying a finding the PR did not cause.
